# UseGeo sparse-SfM 2.5D mesh integration baseline — frozen v1

2026-09-18. This is a minimal real-image integration baseline, not a professional dense-reconstruction method. Frozen before the first reconstruction; no method scores were used for configuration selection.

## Frozen proposed method (before viewing evaluation scores)

- Inputs: exactly the existing 828 `rgb-oriented` images and publisher orientation-table **camera centers only** (224/327/277). No publisher MVS, LiDAR, GT depth, observations or evaluator outputs accessible during reconstruction. Ignore OPK and publisher principal point; SfM estimates camera geometry from RGB.
- Runtime: CPython 3.10.20, pycolmap 3.12.6, numpy 1.26.4, scipy 1.11.1, CPU execution. Library options not explicitly overridden use defaults from this pinned version, exported before execution. Same settings for all scenes. No score-driven configuration selection.
- Features: CPU SIFT, maximum image dimension 1600, maximum 8192 features, standard PyCOLMAP PER_IMAGE/SIMPLE_RADIAL initialization from actual image dimensions/EXIF with library default focal factor when no EXIF estimate exists. No assumed common dimensions or publisher intrinsics/OPK. Keep pinned mapper calibration-refinement defaults. Export actual cameras and all effective options; this is algorithm initialization, not publisher calibration.
- Matching: union of native sequential (overlap=5, quadratic_overlap=False, expand_rig_images=False, loop_detection=False) and spatial (Cartesian allowed centers, ignore_z=False, max_num_neighbors=10, max_distance=1e9 metres). Native spatial asks k+1 neighbors then removes self, so up to ten other neighbors per image, with the pinned library tie behavior. It centers positions before float32 indexing. Export actual normalized pair lists and counts. No custom matching solver or score-driven pair selection. Set `set_random_seed(917)` and one thread in extraction, matching, pair generators, mapper and BLAS environment; no fallback configuration.
- Use the reconstruction registering most input images; break ties by model ID, never evaluator score. Report all input IDs and all registered/unregistered IDs. Partial registration is legal and remains visible; no undocumented coverage threshold.
- Estimate one proper global isotropic similarity from **all registered camera centers in the selected model** to matching allowed publisher centers via native non-robust `estimate_sim3d` (ordinary unweighted fit, no RANSAC, no residual subset selection, no ICP). Require >=3 centers, rank >=2, positive finite scale and proper rotation; log all residuals without filtering. Apply transform inside the method; scorer remains identity alignment. Other disconnected models are reported as excluded by the fixed model-selection rule, not fused opportunistically.
- Surface: transform genuine SfM triangulated points to the native frame; finite points only, one representative per exact XY duplicate (largest track length, then point ID). Delaunay triangulate XY using scipy, retaining every valid nonzero-area triangle; no LiDAR-guided cropping or hole filling. Height from the actual triangulated 3D points. This may bridge unsupported gaps and does not represent vertical/multilayer surfaces; these are disclosed method limitations, not evaluator defects. No publisher point cloud is used.
- Output: strict double-precision vertex / triangular-face `mesh.ply`, method configuration, actual library-option dump, input/output hashes, all image-registration status, center-fit transform/residuals, reconstruction model, commands/logs and resource cost. Validation/export must not alter scoring code or protected inputs.

## Evaluation and limits

All three UseGeo scenes have participated in evaluator development and must be disclosed as fixed development-used evaluation scenes, not held-out generalization. No formal mesh scores have informed this proposed method. No quality threshold is required for integration, but every scene must produce a legal genuine method mesh and valid frozen evaluator result. This draft does not certify A15 or authorize reporting fixtures as method results. Per-scene budget is 4 hours and 16 GiB sampled aggregate worker-process-group RSS, CPU threads=1. Supervisor samples every 0.5 seconds, terminates on observed breach or unavailable measurement, records failure, never changes parameters. Sampling cannot guarantee absence of sub-interval RSS peaks. Native crash/cancellation leaves logs and failed terminal record when supervisor remains alive; forced supervisor SIGKILL is not recoverable certification.

The parent resource observer launches the fixed worker under the recorded default-deny macOS sandbox profile; only the worker performs reconstruction. The parent observes RSS and does not supply reference data. This split is necessary because macOS does not execute setuid `/bin/ps` inside the sandbox. The worker has no evaluator imports or score-reading path. Launch/configuration records bind the script, this preregistration, profile and allowed input hashes before numerical processing.
